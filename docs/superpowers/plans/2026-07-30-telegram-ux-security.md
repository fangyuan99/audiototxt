# Telegram UX, Multi-Key, and Security Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn AudioToTxt into a private, send-to-transcribe Telegram bot with global settings, health-aware Gemini multi-key rotation, durable job management, secure media handling, and an authenticated opt-in Web UI.

**Architecture:** Introduce small shared modules for secure configuration, key selection, media policy, transcription orchestration, and job scheduling. Keep Telegram and Web code as adapters over those modules; make both Web deployment entrypoints call one app factory. Migrate legacy state before handlers start, then remove sensitive per-user fields and old retained media according to the agreed policy.

**Tech Stack:** Python 3.12, `python-telegram-bot` 21.x, FastAPI/Starlette, `google-genai`, `requests`, standard-library `unittest` and `unittest.mock`.
